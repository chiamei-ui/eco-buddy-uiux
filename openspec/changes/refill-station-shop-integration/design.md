## Context

ECO BUDDY 現實行為 Loop 目前只完整設計了收瓶機路徑（P2 掃碼 → P2b 結果 → P3 餵食），但 user-flow.md §J 明確指出補充站消費同時驅動 HP 和潔淨度。P4 商店同樣僅有概念描述（§G），沒有可交付設計師實作的畫面規格。

本設計涵蓋兩條路徑：
1. **補充站路徑**：補充站現實觸發 → App 掃碼 → 洗劑選購 → 購買 → 數值回饋
2. **P4 商店路徑**：細化既有商店概念為完整畫面規格

設計約束（來自 ECOCO_DESIGN.md）：
- 禁止使用漸層
- 主色 `#FF5000`（orange）、`#060E9F`（blue）、背景 `#F7F9FC`
- 按鈕 CTA 用 `rounded-full`，容器用 `rounded-2xl`
- 卡片：`bg-white rounded-2xl border shadow-sm` + hover lift

## Goals / Non-Goals

**Goals:**
- 定義補充站掃碼觸發頁（P2c）的 UI 結構與行為
- 定義洗劑選購頁（P12）完整元素：品項卡、容量選擇、價格顯示
- 定義購買確認 Modal（P12b）：支付方式、點數餘額顯示
- 定義購買完成回饋頁（P12c）：HP + 潔淨度雙數值上升動畫規格
- 細化 P4 商店頁：分類 Tab、道具卡 Grid、購買 Modal、點數來源彈窗

**Non-Goals:**
- 補充站後端 API 整合（本次為 UI/UX 設計規格，非前端實作）
- 補充站實體硬體介面設計
- 洗劑庫存管理系統
- P4 商店金流實作細節（Apple Pay / Google Pay SDK 整合）

## Decisions

### D1：補充站路徑對齊收瓶機路徑結構

補充站掃碼流程刻意對齊收瓶機 P2/P2b 結構，讓使用者建立一致的「掃碼 → 結果 → 回首頁」心智模型。

| 收瓶機路徑 | 補充站路徑 |
|-----------|-----------|
| P2 掃描 QR Code | P2c 補充站掃碼 |
| P2b 回收結果頁（食物 + HP） | P12 洗劑選購頁 |
| P3 餵食 → 數值更新 | P12b 確認 → P12c 數值回饋 |

**替代方案考量**：曾考慮補充站直接彈出 Modal 而非獨立頁面，但洗劑品項需要選擇（容量/種類），Modal 空間不足，故採獨立頁面。

### D2：補充站與 P4 商店保持獨立路徑

補充站觸發入口來自「現實世界掃碼」（青色觸發節點），P4 商店觸發來自「底部 Tab 主動進入」，兩者服務不同使用情境，不合併。

但 P4 商店的「洗劑」分類 Tab 可作為補充站路徑的備援入口（使用者沒有在現實補充站時仍可瀏覽洗劑），兩者共用 P12 洗劑選購頁。

### D3：P12c 雙數值回饋頁設計

補充站消費同時驅動 HP + 潔淨度，回饋頁需同時展示兩個數值上升，採用：
- 並排屬性條（HP 左、潔淨度右）
- 各自獨立計數動畫（數字遞增）
- 角色 Idle 動畫持續播放（不需新增動畫 state，降低採購成本）

### D4：P4 商店點數來源彈窗

user-flow.md §G 提到「右上顯示用戶點數 → 點擊看點數來源」，設計為底部 sheet（非全屏 Modal），顯示：回收次數、補充站消費、任務獎勵等來源分項。

## Risks / Trade-offs

- **[Risk] 補充站現實 QR Code 格式未定義** → 設計階段先以佔位元件表示，格式確認後補 spec
- **[Risk] 洗劑品項清單由後端提供，Phase 1 可能為靜態假資料** → 設計規格以動態資料結構定義，Phase 1 可硬編碼
- **[Trade-off] P12 獨立頁面增加跳轉層數** → 接受此代價以確保品項選擇空間足夠
- **[Risk] P12c 雙數值動畫若角色狀態同時更新，可能觸發型態切換動畫** → 規格需定義：數值動畫結束後再判斷進化，不同步觸發

## Open Questions

1. 補充站 QR Code 觸發機制：是機台掃描、店員操作還是 NFC？影響 P2c 畫面設計
2. 洗劑品項是否需要分類（洗碗精 / 洗衣精 / 其他）？影響 P12 Tab 結構
3. P4 商店「洗劑」Tab 是否永遠顯示，還是僅在使用者接近補充站時出現（geo-trigger）？
4. 補充站消費點數換算比率（影響 P12 價格顯示 UI 密度）
