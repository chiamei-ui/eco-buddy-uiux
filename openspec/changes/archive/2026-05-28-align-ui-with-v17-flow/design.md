## Context

`docs/user-flow.md` v1.7（2026-05-28）為 Phase 1 快閃驗證的權威流程文件，已對齊 2026-05-27 PM 決策包（`docs/pm_decisions_20260527/`）。目前 hi-fi 與 wireframe 原型部分頁面仍停留在舊換算公式、舊 Tab 文案、單軌商店與舊推播入口，與 v1.7 不一致。

本次設計僅處理 **UI 層** 的對齊：畫面結構、文案、互動、視覺狀態。資料來源（後端結算公式、配額重置 cron、推播後端）由其他 change 負責，UI 僅按文件呈現。

利害關係人：
- **PM**：確認 UI 呈現符合 PM 決策（#2/#3/#4/#5/#16/#17/#18/#19/#20/#21）。
- **設計師**：交付更新後的畫面規格與 hi-fi。
- **前端工程師**：依 UI_SPEC 實作 Phase 1 快閃驗證頁面。

## Goals / Non-Goals

**Goals:**
- 將 v1.7 流程文件中的所有 UI 相關決策落地到對應頁面的 `UI_SPEC.md` 與原型畫面。
- 統一全站文案：HP → 精神、潔淨度 → 清爽、任務 → 今日陪伴、圖鑑 → 夥伴日誌。
- 建立 P2 統一掃碼路由邏輯的視覺呈現（recycling / refill 動態頂部標示）。
- 明確 P2b / P12 的雙狀態結構（配額未用完 / 已用完；雙數值並排計數）。
- 整理 P4 商店雙軌制的視覺分區規則與貨幣標示。
- 統整推播文案表與觸發閾值，集中在 `docs/user-flow.md` §A / §J 對應的規格附錄。

**Non-Goals:**
- 不處理金流串接、訂閱 SDK、IAP 商品上架流程。
- 不處理後端配額計算、衰減 cron、推播後端服務串接。
- 不新增 Phase 2+ 範圍（多角色、年度通行證、36 格圖鑑、餵食 / 道具動畫採購等）。
- 不調整 Phase 1 Brief 已定的 Rive 動畫採購範圍（Idle Loop + 點擊反應）。

## Decisions

### D1 — P2 路由：用「同一頁 + 動態頂部標示」而非兩個頁面
v1.7 §D2 明確「同一掃碼頁，QR code 解析後 machine_type = refill 觸發此路徑」。
- **選擇**：保留單一 P2 掃碼頁，QR 解析後 in-place 切換頂部標示（「補充站」/「回收」），再以結果頁分流（P2b / P12）。
- **替代**：兩個入口分別開掃碼頁。被否決，因為用戶實際拿手機對機台 QR 時不知道機型，且 v1.7 已定案統一入口。

### D2 — P2b 雙狀態合併在同一頁，不切換 route
配額用完 / 未用完是同一掃碼事件的兩種結果，使用同一頁 layout 並依後端回傳切換內容區塊：
- 配額未用完 → 食物種類 + 數量 + HP + 雙 CTA（馬上餵 / 先放食物欄）
- 配額已用完 → 僅 HP + 「本週食物已領完」提示 + 單 CTA（完成）
- 兩者皆顯示下週食物預告（週日 12:00 起）。

### D3 — ℹ️ 換算說明使用「摺疊區」而非 tooltip 或獨立頁
v1.7 §P2b / §P12 都標註 #19「公開公式，不糊主畫面」。
- **選擇**：底部加入可展開 / 收合的「換算說明」區塊，預設摺疊，點擊展開公式表。
- **替代**：Tooltip（資訊量過大不適合）、獨立說明頁（增加離開主流程的摩擦）。

### D4 — 屬性 / Tab 文案改為全站替換，不做 i18n 切換層
PM 決策已定案「精神 / 清爽 / 今日陪伴 / 夥伴日誌」為對外用語。
- **選擇**：直接修改原型與 UI_SPEC 文字常數，不引入文案 key/i18n 層。
- **理由**：Phase 1 為中文單一語系快閃驗證，不需要 i18n；後續若做多語再導入。

### D5 — 觸碰互動上限以 UI 即時計數 + 後端核對雙軌
觸碰 +1 心情、每日 10 次。
- **UI 規則**：前端追蹤當日點擊次數，達 10 次後角色仍可播放點擊反應動畫但不再增加心情值（避免「點不動」的死感）。
- **後端核對**：由後端最終結算當日心情上限，避免前端篡改。本次 UI 設計只需呈現「達上限後動畫照常、數值不再變化」。

### D6 — P4 商店雙軌以「分區 Tab 內貨幣 Badge」而非分開兩個入口
雙軌制不是兩個商店，而是同一商店內的兩種商品。
- **選擇**：分類 Tab 橫向滾動保留（食物 / 玩具 / 裝扮 / 氣氛），每張卡片右上以「💎 愛心」或「💳 NT$」Badge 標示貨幣。月底衝刺禮包 22–28 日獨立區塊置頂。
- **替代**：分為「愛心商店」/「付費商店」兩個 Tab。被否決，因為會破壞「按品類找東西」的心智模型。

### D7 — 推播文案集中表化，由 PM/Copy 維護
推播文案散在 v1.7 §A、§J 兩處，內容相同。
- **決定**：在 UI_SPEC 中建立單一「推播文案表」附錄，A / J 處改為引用。避免兩份文案漂移。

## Risks / Trade-offs

- **[文案大規模替換可能遺漏]** → 建立全站「禁用詞」與「對應詞」對照表（已在 `docs/pm_decisions_20260527/ECO_Buddy_文案對照表.md`），由 review 階段掃描原型截圖 + 程式碼字串。
- **[P2 動態頂部標示在 QR 解析失敗時的視覺空狀態未定義]** → 本 change 補上「對準中 / 解析失敗 / 解析成功」三狀態的頂部 banner 設計。
- **[配額用完狀態與下週預告同時出現可能資訊過載]** → 在 P2b 內以視覺層級區隔：主區塊 HP 數值（大）、副區塊「本週已領完」（中）、底部摺疊式預告（小）。
- **[觸碰上限到達後無視覺回饋會被誤判為 bug]** → 補上「達 10 次後角色動畫照常但屬性條無變化」的設計註記，並可加入低調的「Buddy 今天很滿足」微提示（Phase 2 再決定是否實作）。
- **[商店雙軌 Badge 視覺差異不夠會混淆]** → 規範「💎 愛心」配橘色文字、「💳 NT$」配藍色文字，並做對比測試。

## Migration Plan

1. **文件層**：先更新 `docs/UI_SPEC.md` 與必要的 `docs/ECOCO_DESIGN.md` 文案規則，作為畫面更新的 source of truth。
2. **原型層**：依更新後的 UI_SPEC 同步 hi-fi（P1 / P2 / P2b / P4 / P5 / P7 / P9 / P9b / P12）。
3. **跨頁全域**：最後一波處理 Tab Bar / Header / Badge 文案的全站替換。
4. **驗收**：以 v1.7 流程文件逐項對照原型截圖，由 PM 簽核。
5. **回滾**：本次純文件 + 原型更新，回滾即還原 git。無資料庫 / API 變更。
