## MODIFIED Requirements

### Requirement: 動態數值定義清單
系統 SHALL 維護一份「動態數值清單」，列出所有不得在前端 hardcode 的遊戲數值，以及對應的 API 欄位名稱與 UI 顯示位置。食物發放上限、回收轉食物比例、潔淨增量、餵食 random 體力效果 SHALL 由後台設定或後端計算後回傳，前端僅負責呈現結果。

**MODIFIED**：2026-06-08 決策新增食物上限、潔淨當下結算、餵食 +1~5 random 的動態值責任。

#### Scenario: 道具效果值為動態數值
- **WHEN** 前端渲染道具效果值（逗貓棒心情值、梳子潔淨值、零食體力值等）
- **THEN** 數值 SHALL 來自 API response 欄位，前端程式碼不得包含任何具體數字常數

#### Scenario: 食物餵食效果由後端決定
- **WHEN** 用戶在 P1 餵食食物
- **THEN** 後端 SHALL 回傳本次體力增量，範圍為 +1~5，前端不得自行 random

#### Scenario: 食物產出比例為動態數值
- **WHEN** 後端計算本次回收產生多少食物
- **THEN** 預設 SHALL 依 N 個資收物 = N 個食物計算，且可受後台上限與比例設定調整；前端僅顯示後端回傳的食物數量結果

#### Scenario: 潔淨增量由後端回傳
- **WHEN** 回收完成
- **THEN** 後端 SHALL 回傳本次潔淨增量，前端在 P2b 顯示並於返回 P1 時播放對應動畫
