## 一、P1 夥伴頁調整

### 1. 三維數值增量動態改用 ICON

- 現況：餵食或使用道具後，體力 / 潔淨 / 心情增量以文字跳出顯示（如「體力 +10」）。
- 決議方向：**移除增量文字，改用三維對應 ICON 跳出動態**，不顯示「體力」「潔淨」「心情」等中文字樣。
- 原因：視覺更直覺、減少資訊噪音。
- 確認：
  - ICON 使用既有素材：`reference/eco-buddy_hi-fi/assets/` 中的 `icon-hp`、`icon-clean`、`icon-mood`。
  - **顯示格式：ICON + 數字**（如 🔵 `+10`），不能只有 ICON。
- 待確認：
  - [ ] UI/UX 確認三維 ICON 動態方向（跳出位置、消失時間）

### 2. 免費道具 ICON 改為魔術棒

- 現況：P1 夥伴頁免費道具廣告入口按鈕顯示鑰匙 ICON。
- 決議方向：**P1 夥伴頁的廣告入口按鈕改為魔術棒 ICON**。
- 確認：**範圍僅限 P1 夥伴頁此按鈕，不套用至其他畫面**。

### 3. 角色狀態名稱加入編號

- 現況：Buddy 狀態以名稱呈現（如「普通」「開心」「超嗨」）。
- 決議方向：**狀態名稱加入流水編號**，格式如 `#6`。
- 確認：
  - 編號對應 `docs/decisions/CURRENT.md` 的狀態定義。
  - **編號對用戶可見**（不只是開發識別用）。

### 4. 新增下週食物預告欄位

- 現況：P1 食物欄只顯示本週可取得 / 已持有食物。
- 決議方向：**在 P1 夥伴頁新增「下週食物預告」欄位**，提前告知用戶下週可獲得的食物種類。
- 確認：
  - 資料來源：**前端規則產生**（非後端 API）。
  - 顯示內容：**只顯示種類**，不顯示數量。
  - 視覺位置：UI 待設計。
- 待確認：
  - [ ] UI/UX 設計預告欄位視覺位置（食物欄下方 / 側邊 / 折疊區）

## 二、遊戲入口吸引策略

### 5. 一般模式首頁懸浮入口

- 背景：ECO BUDDY 遊戲模式與一般 ECOCO App 共存，初期需主動引導用戶進入遊戲。
- 決議方向：**一般模式首頁新增懸浮按鈕或 GIF 動畫**，吸引用戶點擊進入遊戲模式。
- 確認：細節上線前規劃，**支援後台設定**（觸發條件、顯示時機）。
- 待確認：
  - [ ] 懸浮按鈕 vs. GIF 動畫，選哪種？
  - [ ] 點擊後行為（直跳遊戲模式 P1，還是先跳介紹頁？）

### 6. 個人化 / 客製化角色感受（「我的 Buddy」）

- 背景：希望用戶進入遊戲時感受到「這是我的 Buddy」，而非通用角色。
- 下一步：**由 UI/UX 列出既有功能中可強化個人化感受的項目**，作為 Phase 1 範圍建議。
- 待確認：
  - [ ] UI/UX 列出既有功能相關建議後，PM 確認 Phase 1 範圍

## 四、贈送道具功能（重要）

### 8. 用戶之間互相送禮

- 決議方向：**新增「贈送道具」功能**，用戶可以將持有的道具 / 食物送給其他用戶。
- 通知串接：一般模式個人通知中心推播：**「OOO 送禮物給你囉，快來跟 Buddy 一起玩吧！」**
- 功能影響範圍：
  - 前端：贈送 UI 流程（選擇道具 → 選擇對象 → 確認 → 送出）
  - 後端：道具持有權轉移邏輯、通知觸發
  - 一般模式：通知中心顯示遊戲推播並提供入口跳轉
- 待確認：
  - [ ] 可贈送的道具 / 食物範圍（全部？排除課金商品？）
  - [ ] 每日 / 每週贈送次數上限？
  - [ ] 每次可贈送數量上限？
  - [ ] 收禮方是否需確認接受，還是自動入帳？
  - [ ] 通知點擊後跳轉行為（直跳 P1 / 跳禮物收件頁？）
  - [ ] 贈送對象範圍（僅好友？還是任意用戶）？

### 9. 禮包課金商品需提早規劃平台上架

- 現況：禮包內容可彈性設計，但若包含課金商品（IAP），須在 App Store / Google Play 各自逐一上架審核。
- 決議方向：**IAP 商品需提早規劃，逐一上架**，避免上線時尚未通過審核。
- 待確認：
  - [ ] 哪些禮包商品屬於 IAP 範圍（裝扮 / 稀有食物 / 道具）？
  - [ ] IAP 上架排程由誰負責追蹤？
  - [ ] 禮包贈送是否允許包含 IAP 商品？（平台政策問題）

## 六、連續登入機制

### 11. 連續登入以「7 天」為單位，不以週曆計算

- 決議：
  - 連續登入計算單位為**連續 7 天**（非自然週一到週日）。
  - 連續登入滿 7 天 → 觸發 **#34 特殊形態**（`has_disco=true`，派對動物）。
  - 若觸發 #34 形態時**潔淨 > 90** → 同時觸發 **#29 狀態**。
  - P5 今日陪伴頁 UI **可預告**連續登入進度與里程碑獎勵。
- 確認：狀態定義與觸發條件已收錄於 Rive 規格書，UI 呈現待設計。
- 與 2026-06-22 討論對齊：連續天數不每 7 天歸零，持續累加。
- 待確認：
  - [ ] P5 預告欄 UI 呈現方式（進度條 / 日曆格 / 文字）
  - [ ] 連續 7 天後第 8 天起，#34 形態是否維持至月底？

### 12. 簽到自動觸發 + 免費補簽

- 決議：
  - **登入即自動觸發當日簽到**，不需用戶手動點擊。
  - **提供補簽功能**：漏登後可點擊補簽，**免費、無需購買或道具兌換、無次數限制**。
  - **補簽時間範圍：只能補昨天**（不開放補更早的日期）。
  - **補簽後連續天數即時更新**。
  - **重置後，本月已觸發的 #34 形態當月仍維持**（不跟著重置）。
- 影響：
  - P5 今日陪伴頁需有補簽 CTA（漏簽日顯示「補簽」按鈕）。
  - 後端需支援補簽 API。

#### 天數計算與重置邏輯（設計師建議，待 PM 定案）

連續天數採**個人化第 1–7 天循環**，非自然週一到週日：

| 情境 | 說明 | 結果 |
|------|------|------|
| A｜連續成功 | 第 1–7 天全數登入 | 第 7 天觸發 #34，次日進度歸零重新從第 1 天算 |
| B｜漏登 1 天 | 第 4 天未登入，第 5 天登入後補簽第 4 天 | 連續紀錄不中斷 |
| C｜漏登 ≥ 2 天 | 第 4、5 天均未登入，第 6 天登入時第 4 天已死棋 | **當下強制重置為第 1 天**，廢棄舊進度 |

- 待確認：
  - [ ] PM 確認上述三情境邏輯是否定案
