\#3 數值換算

✅ 回收(收瓶機):  
   \- 杯子:每個 \+1 HP  
   \- 寶特瓶/鋁罐/牛奶瓶:每個 \+2 HP  
   \- 退瓶不計算  
   \- 其餘數值規則比照 ECOCO 點數現行邏輯

✅ 回收(電池機):  
   \- 1 號/2 號電池:每顆 \+10 HP  
   \- 其餘規格電池:每顆 \+5 HP

✅ 補充站:  
   \- 每消費 NT$10 \= \+10 HP \+ \+10 潔淨  
基本上就1元/1+1

✅ 道具效果(配合補充站數值校準):  
   \- 逗貓棒:心情 \+15  
   \- 小球:心情 \+15  
   \- 梳子:潔淨 \+15、心情 \+10  
   \- 零食:HP \+15、心情 \+15

理由:  
1\. HP 主要靠線下回收與補充站消費,確保核心 O2O 行為被獎勵  
2\. 電池機數值較高,反映正確處理危險廢棄物的環境價值  
3\. 道具數值與補充站消費對齊(NT$10 級距),  
   讓「廣告/課金道具」與「實際消費」的價值感一致,  
   避免道具看起來太弱、沒人想抽

### \#16 點數體系：沿用 ECOCO 點數 vs. 獨立遊戲幣

**問題**：一般模式使用的 ECOCO 點數，在遊戲模式是否沿用，還是另起一套 ECO BUDDY 專屬遊戲幣？

| 方案 | 說明 | 潛在影響 |
| :---- | :---- | :---- |
| 沿用 ECOCO 點數 | 兩模式共用同一貨幣，餘額互通 | 設計較簡單；但遊戲感較弱，點數消耗會影響一般模式餘額 |
| 獨立遊戲幣 | 遊戲模式另立貨幣（如「ECO Coin」），與 ECOCO 點數分開 | 遊戲閉環更清晰；需定義兩者兌換關係或取得途徑 |
| 不使用點數 / 遊戲幣 | 商店全面改為現金購買，無虛擬貨幣體系 | 最簡化，但遊戲化誘因消失；與 \#17 現金方案合併討論 |

**影響**：商店 P4（道具購買貨幣顯示）/ P11 次數包購買邏輯 / 全站錢包 UI 是否需分欄顯示

### \#17 商店購買現金流方式

**問題**：P4 商店內的道具 / 次數包購買，採用哪種現金流方案？

| 方案 | 說明 |
| :---- | :---- |
| 遊戲幣購買 | 使用 \#16 定義的點數 / 遊戲幣，無真實金流 |
| 真實金流（IAP） | 串接 App Store / Google Pay 等平台內購 |
| 混合制 | 部分道具用遊戲幣，特定項目（如次數包）用真實金流 |
| 純現金，無虛擬貨幣 | 商店全部現金定價，不引入任何點數或遊戲幣體系（與 \#16 第三選項連動） |

**影響**：P4 商店 UI 價格標示 / P11 次數包購買流程 / 是否需串接第三方金流 SDK；若涉及真實金流需資深工程師 review（依資安規範）  
\#16 \+ \#17 點數體系與現金流(合併決策)

✅ 採雙軌制:ECOCO 點數 \+ 真實金流並行,但商品分區不互通

【ECOCO 點數消費區】  
\- 基礎食物補給包  
\- 一般道具(逗貓棒/小球/梳子/零食)  
\- 清潔用品

【真實金流 IAP 區】  
\- 月底衝刺禮包 NT$199  
\- 月度通行證 NT$149  
\- 稀有限定裝飾(永久穿戴)  
\- 圖鑑加速/特殊道具

【規則】  
\- 點數與現金不互換、不互買  
\- 商店 UI 每個商品明確標示「💎 點數」或「💳 NT$」  
\- 不發任何遊戲幣

理由:  
1\. 強化 ECOCO 點數價值,反向拉動一般模式回收行為  
2\. 保留真實金流收入(月底禮包/通行證等高 ARPU 商品)  
3\. 對應企劃書「免費路徑 vs 付費路徑」雙軌設計  
4\. 用戶心智清楚,工程複雜度與純 IAP 方案相當

備註:  
\- IAP 串接需資安 review  
\- 需設計點數消費的單日/單次上限,避免一般模式餘額被洗光  
\- 道具/禮包定價待後續另定

### \#19 P2b / P12 是否串接機台實際數據

**問題**：P2b（回收結果頁）與 P12（補充站結果頁）是否顯示機台回傳的實際數值，並公開換算三維數值的公式？

**各方立場**：

- 前端工程師：若要顯示實際數據，需與後端串 API，工時增加

| 方案 | 說明 |
| :---- | :---- |
| 顯示實際數據 \+ 公開公式 | 透明度最高；需後端 API、工時最長 |
| 顯示實際數據，不公開公式 | 仍需 API；透明度居中，仍有黑箱風險 |
| 不顯示實際數據，僅顯示遊戲結果 | 工時最短；可能被客訴黑箱 |

**影響**：P2b / P12 UI 數值欄位設計 / 後端 API 串接範疇 / 工時估算

\#19 P2b / P12 機台數據 ✅ 顯示實際數據 \+ 公開公式 ✅ 公式放在「ℹ️ 換算說明」摺疊區,不糊主畫面

 理由:透明是 ECOCO 品牌核心,黑箱客訴的長期成本高於後端工時
