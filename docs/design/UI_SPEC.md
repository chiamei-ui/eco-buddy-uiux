### Buddy 的餐袋 Sub-Tab（#29.1 定案）

- 格數：4 格固定（1×4 橫排）
- 顯示規則：4 格全顯示，未解鎖格顯示灰色虛線佔位（🔒）
- 庫存數字 Badge：左上角顯示，**每格上限 `[API: food_slot_max_count]` 個**（後台可調，預設 12）

**Badge 視覺三狀態**：

| 狀態 | Badge 顏色 | 觸發條件 |
|------|-----------|---------|
| 庫存充足 | 橘色 `#FF5000` | 庫存 ≥ 4 |
| 庫存低 | 黃色 `#FFCE00` | 庫存 1–3 |
| 未解鎖 | 灰色 + 🔒 icon | 該格尚未解鎖 |

**每週配額制**：每種食物每週上限由後台設定（既有參考值 5 個，週三 12:00 重置）；N 個資收物 = N 個食物，達上限後不新增食物格庫存，但潔淨仍需當下結算。週日 12:00 起食物欄底部顯示「下週食物預告」入口。

**互動規則**：

| 操作 | 結果 |
|------|------|
| 純點擊食物格（有庫存） | 角色對話泡泡提示「拖曳餵食」 |
| 純點擊食物格（庫存歸零） | 角色對話泡泡：「沒東西吃了 😢 去帶食物回家！」 |
| 點擊鎖定格 | 角色對話泡泡：「這個還沒解鎖，再努力一下！🔒」 |
| 拖曳食物格 → 角色展示區 | 觸發餵食動畫（P3）|
| 拖曳食物格（庫存歸零） | 角色對話泡泡提示補充 |

**Drop Zone**：角色展示區整塊（dragover 視覺高亮縮放 + 橘色陰影，待動畫資源到位後由動畫師角色反應取代）

**從 P2b「先放食物欄」返回後的入場動態**：

當用戶在 P2b 點擊「先放食物欄」返回 P1 時，P1 食物欄需呈現以下動態，持續至用戶互動或 3 秒後自動消失：

| 元件 | 動態效果 | 規格 |
|------|---------|------|
| 新增食物的格子 | 橘色光暈脈衝 `ring-pulse`：外框從 `#FF5000` → 透明 → `#FF5000`，循環 2 次 | 持續約 2s，完成後回 Badge 正常高亮態 |
| Badge 數字 | 縮放 pop：`scale 0.8 → 1.2 → 1.0`，數字同步更新為最新庫存 | 單次，duration 400ms |
| Buddy 對話泡泡 | 顯示「幫我存好了！等你準備好再給我～」 | 10 秒自動消失，可點 ✕ 提早關閉 |
| Sub-Tab 焦點 | 若用戶當前在「道具包」Tab，自動切換到「Buddy 的餐袋」Tab | 切換無動畫，直接入場 |
| 潔淨增量 | Buddy 或潔淨狀態條附近顯示「+N 潔淨」浮動動畫 | 來自 P2b `clean_delta`，duration 約 1.2s，不遮擋食物格 Badge |

> 設計注意：若本次存入的食物跨越「庫存低 → 庫存充足」閾值（庫存從 1–3 跳至 ≥ 4），Badge 顏色需在 pop 動畫完成後從黃色 `#FFCE00` 切換至橘色 `#FF5000`。

### 道具包 Sub-Tab

- 佈局：與食物欄同區域切換
- 右上角「**管理 ›**」按鈕 → 跳轉 P9 道具背包
- 互動規則：與食物欄拖曳邏輯相同（拖曳 → 觸發道具使用動畫）
- Sub-Tab 不顯示任何副標文字；拖曳引導改由點擊格子時的 Buddy 對話泡泡提供

**道具格三態視覺規格**：

| 狀態 | 觸發條件 | 卡片視覺 | 右上角 Icon |
|------|---------|---------|------------|
| 正常 | 有效期 > `[API: tool_warn_threshold_hours]` h（或永久類） | 正常顯示 | ℹ️ |
| 即將過期 | 有效期 ≤ `[API: tool_warn_threshold_hours]` h 且 >0 | 正常顯示 | 橘色 ⏰（取代 ℹ️）|
| 已過期 | 有效期 ≤0 | `opacity: 0.4` + 名稱顯示刪除線 | ✕（取代 ⏰ / ℹ️）|

> `[API: tool_warn_threshold_hours]` 為後台可調閾值（預設 24h），前端依此判斷三態切換，不寫死數字。

**三態 icon 優先級**：✕ > ⏰ > ℹ️（互斥，同一角落依狀態切換，不堆疊 icon）

**已過期道具規則**：
- 禁止拖曳（拖曳事件不觸發，視覺無回應）
- 過期後 24h 從玩具箱靜默移除，不顯示任何通知

**點擊觸發 Buddy 泡泡規則**：

| 道具格狀態 | Buddy 泡泡文案 |
|----------|--------------|
| 有效期 >24h（正常格） | 「拖到我身上，記得今天就用掉喔！」 |
| 有效期 ≤24h（即將過期） | 「這個快消失了！今天要用掉喔 ⏰」 |
| 已過期 | 「嗚… 這個不見了 😔」（不觸發任何操作） |

**ℹ️ icon 規格（食物格與道具格共用）**：
- 食物格：右上角常態顯示 ℹ️ icon
- 道具格：右上角依三態優先級顯示 ✕ / ⏰ / ℹ️（有效期 ≤24h 或已過期時 ℹ️ 隱藏）
- 卡片本體移除效果值文字；效果值僅在 ℹ️ Bottom Sheet 顯示
- 點擊 ℹ️ icon → 彈出 Bottom Sheet，不觸發格子的拖曳起始事件（`stopPropagation`）

### ℹ️ Bottom Sheet 規格

點擊食物格或道具格 ℹ️ icon 後，底部 Sheet 顯示完整效果值資訊。

**食物格 Sheet 內容**：

| 欄位 | 內容 |
|------|------|
| 大圖 | 食物插圖（放大版） |
| 名稱 | 食物名稱 |
| 效果值 | `[API: food_hp_random_range]`（顯示「每次餵食體力 +1~5」或後端回傳等價範圍，不 hardcode 固定 +10/+15） |
| 週配額 | 剩餘數量 / `[API: food_weekly_quota]` 或後台上限（如 `本週剩 3 / 5`） |

**道具格 Sheet 內容**：

| 欄位 | 內容 |
|------|------|
| 大圖 | 道具插圖（放大版） |
| 名稱 | 道具名稱 |
| 效果值 | 各道具依 API 欄位顯示：逗貓棒 `[API: tool_cat_wand_mood_effect]` / 小球 `[API: tool_ball_mood_effect]` / 梳子 `[API: tool_brush_clean_effect]`+`[API: tool_brush_mood_effect]` / 零食 `[API: tool_snack_hp_effect]`+`[API: tool_snack_mood_effect]` |
| 有效期類型 | 免費 `[API: tool_free_expire_hours]`h / 付費 `[API: tool_paid_expire_days]` 日 / 永久 |

**通用規則**：
- 效果值從資料層動態帶入，與 GAME_MECHANICS.md 保持一致；前端不 hardcode 數值
- 點擊 ℹ️ icon 僅彈出 Sheet，不觸發格子的拖曳起始事件（`stopPropagation`）
- 關閉方式：點擊 Sheet 外區域 / 下滑

**✕ / ⏰ / ℹ️ 互斥邏輯（三態優先級）**：

| 優先級 | Icon | 觸發條件 |
|--------|------|---------|
| 最高 | ✕ | 有效期已到期 |
| 中 | ⏰ | 有效期 ≤24h 且 >0 |
| 低（預設） | ℹ️ | 有效期 >24h 或永久類 / 食物格 |

三種狀態互斥，同一角落依狀態切換，不堆疊 icon。永久類道具不顯示任何時效 icon，僅顯示 ℹ️。

### 免費道具浮動按鈕

- 位置：右側浮動按鈕下方（橘色圓形）

- 次數用完：Badge 顯示 0，按鈕進入 disabled 樣式
- 點擊行為：彈出底部 Sheet → P6 廣告流程

### 角色互動（觸碰 Buddy）

| 操作 | 結果 |
|------|------|
| 點擊 Buddy（當日 < `[API: tap_daily_limit]` 次） | 點擊反應動畫（歪頭 / 跳一下 / 揮手）+ 心情值 `[API: tap_mood_gain]` |
| 點擊 Buddy（當日 ≥ `[API: tap_daily_limit]` 次） | 點擊反應動畫照常播放，心情值不再增加 |
| 拖曳食物/道具 → 角色展示區放開 | 觸發對應動畫 |

> **設計注記（D5）**：達每日上限後動畫仍播放，避免「點不動」的死感。前端追蹤當日次數，後端最終核對心情上限。`tap_mood_gain`（每次心情增量）與 `tap_daily_limit`（每日上限次數）均為後台可調數值，前端不寫死。

## P2b — 回收結果頁

- 形式：全屏頁面，底色 `#0A0A0A`（深黑），slide-up 動畫（`translateY(100%) → 0`）
- 頂部暖色區：
  - `RECYCLE COMPLETE · 帶食物回家`（橘色標籤）
  - `Buddy 收到禮物了！`（大標題）
  - 時間 + 地點
  - **大字總量**：本次回收總量，例如 `帶回 6 件`
  - 小字細節：機台類型 / 投入品項 / 食物上限狀態 / 潔淨增量

### 回收總量與機台互斥

- 主畫面第一視覺為本次回收總量，字級高於其他數字。
- 收瓶機與電池機為不同機台；P2b 同一次結果不得同時顯示投瓶數與投電池數。
- 收瓶機模式：顯示投入瓶罐數、退瓶數、實際獲得食物數、潔淨增量。
- 電池機模式：顯示投入電池數、電池品項摘要、實際獲得食物數、潔淨增量。
- 若 API 回傳混合資料，顯示資料異常狀態，不自行合併。

### 食物與潔淨結算

| 結算項 | 規則 | UI 呈現 |
|--------|------|---------|
| 食物 | N 個資收物 = N 個食物，受後台上限限制 | 食物卡片列 + 實際入帳數 |
| 潔淨 | 必得，當下結算；淨增量 clamp ≥0，≤0 顯示 0 | `+N 潔淨`，返回 P1 後再播放浮動動畫 |
| 體力 | 不在回收當下直接結算；餵食時後端回傳 +1~5 random | P2b 不顯示體力預計補充卡 |

**潔淨換算規則（#29.5 定案）**

| 機台 | 投入 | 退回 |
|------|------|------|
| 收瓶機 | +2 / 個 | -1 / 個；淨值 clamp ≥0 |
| 電池機 | +5 / 顆 | -1 / 顆；淨值 clamp ≥0 |

> ℹ️ 換算說明摺疊區需顯示機台對應的規則；前端只呈現後端回傳的 `recycle_clean_delta`，不自行計算。

### ℹ️ 換算說明摺疊區

- 預設：摺疊（顯示「ℹ️ 數據細節 ›」文字連結）
- 點擊展開：顯示本次品項、食物上限、潔淨結算與後端回傳欄位
- 位置：主內容區下方，CTA 按鈕上方

### 中段白底（依食物上限狀態切換）

**情境一：食物未達上限**

- `本次 Buddy 獲得` 標題
- 食物卡片列（圖示 + ×數量 + 名稱）

- 單 CTA：`先放食物欄`（橘色 `rounded-full`）→ 食物存入 P1 食物欄 + 返回首頁 + 顯示「+N 潔淨」動畫

> **#22 定案**：移除「馬上餵 Buddy」快捷按鈕；食物統一先存入食物欄，於 P1 拖曳完成餵食。

**情境二：食物已達上限**

## 變身（Buddy 狀態切換）

- **用語**：一律使用「**變身**」，禁止「進化」
- 過渡動畫：由動畫師定義（Rive 另案）；動畫未交付前 UI 層以簡單過場演示
- 觸發後：自動推播通知（見附錄 A §A7 型態改變）

### 觸發時機（各畫面）

| 畫面 | 觸發點 | 說明 |
|------|--------|------|
| **P1** | 餵食動畫結束後 | 食物拖曳放開 → 餵食動畫播完（≈1.5s）→ 判斷變身 |
| **P2b** | 按下 CTA 後 | 「先放食物欄」或「完成」按下 → 判斷變身 → overlay 結束後跳 P1 |
| **P12** | 計數動畫結束後 | 體力／潔淨進度條跑完（≈1.6s）→ 判斷變身；不與計數同步觸發 |

### UI 層責任邊界

1. **UI 層**：在上表時機判斷是否觸發變身，若是則播全屏 overlay
2. **Overlay 期間**：暫停所有互動，等動畫結束才執行頁面導航
3. **Rive 層**：overlay 播放時 fire `ev_evolve_start`（白光）→ `ev_evolve_burst`（粒子爆發），詳見 `docs/animation/NAMING.md`
4. **Overlay 結束後**：P1 留在原地；P2b 跳 P1；P12 顯示「返回首頁」按鈕
