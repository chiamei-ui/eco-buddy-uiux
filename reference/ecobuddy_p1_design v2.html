P1 核心改動總覽

  • NEW場景式佈局 — 寵物佔畫面 45%，有天空、草地、雲朵，營造「遊戲世界」而非功能清單
  • CHANGED食物由按鈕→泡泡物件 — 橫向滾動 shelf，可拖曳到寵物身上觸發餵食，也可點擊進入 P3
  • CHANGED屬性條→環狀指標 — 三個小 ring 浮在場景右側，hover 顯示數值，不額外佔版面
  • NEW寵物互動 — 點擊寵物觸發對話泡泡 + 愛心粒子，增加情感連結
  • CHANGEDCTA 層級調整 — 掃描 QR 仍為主按鈕，其餘動作改為圖標式三等分

設計 場景式佈局原理

遊戲感的關鍵不是加更多動畫，而是讓使用者感覺「走進了一個世界」。

具體做法：寵物不是放在卡片裡，而是站在一片有天空和草地的場景中。屬性指標不是獨立區塊，而是像遊戲 HUD 般浮在場景邊緣。食物不是功能按鈕，而是可以「拿起來餵」的物件。

下半部白色面板用 border-radius: 24px 抽屜式上推，將功能操作與場景視覺分層，兼顧沈浸感和操作效率。

互動 食物拖曳設計

Demo 中已實作基本版：點擊食物泡泡 → 寵物場景出現該食物 emoji 飄入動畫 + 愛心粒子。

正式版建議：食物泡泡支援 drag，拖到寵物上方 drop 觸發餵食確認。這讓操作從「按按鈕」變成「把東西遞給寵物」，直覺度大幅提升。

鎖定的食物（W3/W4）顯示虛線框 + 鎖頭，不可拖曳。

前端 給工程師的技術備註

  • 寵物區 160×160px 預留給 Rive 動畫容器，目前用 SVG placeholder
  • 環狀指標用 SVG stroke-dashoffset 控制百分比，動態更新只需改一個數值
  • 食物拖曳用 HTML5 Drag & Drop 或 touch events（行動端優先）
  • 場景背景用 CSS gradient 組合，不需額外圖片資源
  • 對話泡泡內容由後端依據寵物狀態動態回傳
  • tab bar 結構不變，保持與現有 wireframe 一致

對比 Before vs After

Before（v6 wireframe）:
寵物區 120px → 屬性條區塊 → 食物四宮格按鈕 → CTA 按鈕 → 底部按鈕
→ 畫面被 5 個功能區塊均分，寵物只是其中一個。

After（redesign）:
